**Status: revised after 3-auditor swarm (spec-fidelity, firewall/leakage, test-completeness).** Every frozen rule → module + tests, zero added degrees of freedom. Two genuine spec ambiguities remain and are flagged **OPEN RULING** below — do not build the affected branch until ruled.

## Firewall (CORRECTED per firewall-audit BLOCKER-1)
The earlier blanket claim "no real markout value computed during the build" was **false**: the counts/feasibility audit must compute the standardization scale σ̂(C,h) and the degeneracy / N_min checks, which are real per-wallet markout aggregates. Corrected discipline:
1. Modules are developed on synthetic + positive-control data. **No real per-wallet markout, ranking, ordering, selected identity, Yband/Aband, θ̂, or verdict is persisted, printed, or human-readable during the build.**
2. **σ̂(C,h) is computed internally ONLY for the finite / non-degenerate-scale check.** The counts report emits a **`scale_valid` boolean only** — the real σ̂ scalar is **never displayed**, and the underlying per-wallet real-markout (`Zbar`) vector is **never persisted, sorted, ranked, or exposed**. σ̂ **cannot influence any threshold or design choice**. Positive controls **recompute their own scales** from each nullized/injected dataset (never reuse real σ̂).
3. Positive-control gate is a PRE-run gate; a **failed** control ENDS Gate-A on this tape as underpowered/invalid (per STOP_RULES, "does not loop"). Any successor design must be justified from the aggregate power diagnostic only — never reverse-engineered from the observed null distribution.
4. Determinism: same seed + same input ⇒ byte-identical (rerun-equality test on modules 7, 14). `GLOBAL_SEED` is pinned in the frozen config (freeze-completion item F1).

## RULINGS — RESOLVED (2026-07-06)
- **R1 — flip residual < $100: DUST WINS.** A flip always updates the ledger and terminates the prior episode, but a residual opening leg below $100 does **not** open a new qualifying episode. *(module 1)*
- **R2 — selection: SCOREABLE cross-section.** Top 10% = top 10% of wallets with valid finite θ̂ in the frozen ranking cross-section; min 20 / max 50; **never pad with unscoreable**; **< 20 scoreable ⇒ no valid basket (fold unrankable).** *(module 9)*
- **R3 — wash/self-cross: WAIVED for v1.0.** No labelled precision claim. Exact same-wallet/both-sides/same-`tid` records are **data-integrity anomalies** (self-trade prevention should preclude them) → inspect/quarantine the affected event/stream; do **not** label the wallet as wash. Related-address wash not identifiable from this tape. *(module 0 drops the wash gate; module 1 adds a same-tid-both-sides integrity-anomaly quarantine reason)*
