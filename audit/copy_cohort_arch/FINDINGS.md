# AUDIT FINDINGS — copy_cohort architecture doc (design-stage swarm, 2026-07-12)

Four agents (stats-rigor, firewall-leakage, docs-consistency, data-integrity) against
`research/studies/copy_cohort/COPY_COHORT_ARCH.md` v1.0, scoped by `SCOPE.md`.
**Disposition: all findings accepted; doc revised to v1.1 in place.** Severity totals:
1 CRITICAL, 4 HIGH, 9 MED, rest LOW/NIT. Clean bills: lane firewall, EB-shrinkage validity,
Stage-0 effect-leakage safety, verdict taxonomy, prior-findings register (all quotes exact),
lib correctness (bh_fdr, sign_test, +1/(B+1) corrections present).

## CRITICAL

- **S1 (stats).** "Headline CI = wider of two one-way cluster CIs" is NOT conservative: under
  simultaneous wallet+week dependence the max-rule envelope covered 80.0% at nominal 95%
  (probe: 30 wallets × 22 weeks, equal shocks). GREEN could fire on noise.
  **Fix (v1.1 §5.5):** CGM two-way combination SE² = SE²_wallet + SE²_week − SE²_iid, t critical
  value at min(G_wallet, G_week) − 1 df; coverage simulation added as a Stage-0 deliverable.

## HIGH

- **W1 (firewall).** Formation selector consumes post-cutoff prices: `close_ts ≤ cutoff` bounds
  the close fill, not the markout window (`entry_bar_ts + h` can end inside the evaluation month);
  straddle-week μ can inject month-T returns into every candidate's score. The lake defers the ≤C
  censor (R10) to the consumer; v1.0 never applied it.
  **Fix (§3 F1, §4):** formation-scoreable requires `entry_bar_ts + h ≤ cutoff` per horizon; all
  formation μ, the EB pool mean, and Arm-B demeaning computed with the `(t+h) ≤ cutoff` censor.
- **S2 (stats).** Power gate vacuous on the selection channel: `inject_positive_control` adds a
  uniform edge, so ANY selector (even hash-ranked) passes end-to-end. **Fix (§6):** planted
  skilled-sub-population control (heterogeneous injection); report top-K capture rate AND
  recovered cohort effect; uniform injection demoted to evaluation-stage-only check.
- **S3 (stats).** MDE computed at the Stage-0 (wallet-nested) cluster level while the headline
  test is two-way clustered → gate can pass while the real instrument is blind. **Fix (§6):**
  MDE = care-about-scaled half-width of the SAME pooled two-way procedure, sized to forward
  dimensions (single months, K=100, ≥3-episode floor applied).
- **S4 (stats).** Stage-0 sign-flip calibration circular as written: flipping at level L and
  testing clustered at L is exact for every L → adoption rule degenerates (and the lib has no
  cluster-flip anyway — docs D1/data). **Fix (§2):** null generated by wallet-level flips
  (coarsest), test statistic clustered at each finer candidate; adopt coarsest candidate below
  wallet whose rejection-rate CI ⊂ band; week (time-block) added to the candidate set;
  n_perm ≥ 2000; `cluster_id` sign-flip support moved to NEW in §9.

## MED (accepted, all folded into v1.1)

- **S5.** Two-sided 5-fold sign test can never reach p<0.05 (min 0.0625) → one-sided
  (pre-registered direction); load-bearing cross-unit test moved to the wallet-level sign test on
  cohort wallets' forward means (n≈100); folds demoted to consistency display.
- **S6.** Placebo miscalibrated both ways: matching missed coin-mix/direction axes (too easy) and
  thin 5×5 strata force real-cohort overlap (too hard) → matching key adds majority-coin share +
  long share; stratum-collapse rule (merge below 3× needed draws); per-fold placebo-overlap
  reported; B→100 with p = (#{≥obs}+1)/(B+1).
- **S7.** Per-fold week-block bootstrap has ~4–5 clusters (probe coverage 84.3%) → per-fold
  interval inference wallet-cluster only; week-block intervals pooled-only, t with C−1 df.
- **W2 (firewall).** Finalize-month partition trap: forward reads pruned by `month=T` drop
  cross-month episodes (conditions outcome on fast closes) → predicate on `open_ts` only, scan all
  partitions, assertion that some forward episodes live in partitions > T; keep OPEN_AT_END rows
  in the 202606 fold.
- **W3 (firewall).** Arm-A close-conditioning (disposition censoring): requiring a close by cutoff
  winner-tilts formation scores → Arm A scoreability = window censor only (no close requirement);
  Arm B keeps `close_ts ≤ cutoff`; asymmetry documented.
- **W4 (firewall).** Power gate sizing + RED's "tight" undefined → RED now requires realized
  forward CI half-width ≤ 5 bp.
- **D1 (data).** ~19–21% of episodes have `entry_after_close` (entry tick after a sub-minute
  episode closed) with non-NULL markout; entry-side ≤90 s bound lives only in features_markout,
  which this study doesn't read → new filter F0: `NOT entry_after_close AND entry_lag_s ≤ 90`.
- **D2 (data/docs).** F9 vault filter undeliverable: `VAULT_SQL` is a fills-level predicate
  (`dir='Net Child Vaults'`); episode `dir` is long/short → no-op. F9 folded into F7's flag
  superset, honestly scoped.
- **D3 (data/docs).** μ(coin, ISO-week) not a built artifact: only the per-minute `fwd_returns`
  primitive is built; the one existing aggregation is hard-coded to a single global cutoff
  (leaky per fold) → §9 row re-labeled; per-fold μ derivation is NEW; `addr_coin_markout`
  forbidden as a μ source; y_lag μ-term construction specified from the primitive.

## LOW / NIT (accepted)

- Cutoff off-by-one hazard: pin `as_of_cutoff_ms(last formation month)` + runtime assertion (W).
- Boundary `≤ cutoff` vs `<`: convention noted, strict `<` adopted (W).
- `power_report` → `power_check` naming (S/D2 docs).
- Column names `raw_markout_*`, `ph_*`; y_lag computed exactly from `ph_5m`/`ph_4h`, NOT by
  subtracting the two markout columns (denominator differs) (docs).
- Endpoint description: entry strictly-after; horizon end backward-ASOF ≤90 s (docs).
- Episodes↔markout join population is `NOT inherited_basis`; never filter on the `month`
  partition key (data).
- eb_shrink degenerate cases specified: τ̂² floor + logged flag, t-stat fallback ranking if
  τ̂²=0, σ_w² = variance of within-wallet cluster means (S9).
- BH input p-values specified: sign-flip p at the frozen cluster level with +1/(B+1) (S10).
